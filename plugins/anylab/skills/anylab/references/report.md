# Единый отчёт по лабораторной

На титуле укажи работу, автора и группу. В основной части дай отдельный раздел для каждого задания. Внутри раздела приведи постановку и значения варианта, опиши модель и проверенные режимы, покажи измерения или графики и сформулируй вывод. Заверши сопоставлением результатов по всей работе. Укажи лист задания и страницы использованных материалов. Снимки подписывай по содержанию. Для PDF вызови `pdf` после создания DOCX и проверь читаемость.

В `report` передай `spec` с полями `lab`, `variant`, `title`, `author`, `group`, `sections`. Раздел содержит `heading`, `paragraphs`, при необходимости `tables` (массив объектов с `columns` и `rows`) и `figures` (абсолютный `path` и `caption`). Можно передать `template` с локальным совместимым образцом. По умолчанию работает нейтральный титул. Пиши выводы по данным текущего запуска. Ссылки на учебное требование привязывай к странице, а значения из образца используй только для того варианта, к которому они относятся.

## Заполнение оформленного DOCX

Из `templates` возьми `report` и JSON `report_fields`. Заполни объект `text` исходными данными, описанием и выводами, `images` абсолютными путями к PNG, `tables` строками с нужным числом столбцов в порядке из `columns`. Передай это в `fill_report`. Данные, которых реально нет, обозначь текстом с причиной и добавь снимок соответствующей схемы или прогона. Используй движок `word` или `libreoffice` для копии PDF с вёрсткой DOCX. Движок `reportlab` подходит для PDF с новой вёрсткой.


## Схемы блоков AnyLogic

Логическую схему модели получай снимком настоящих блоков из редактора AnyLogic или 2D-представления соответствующего ALP. Не заменяй её программно нарисованной блок-схемой: такая картинка скрывает реальные порты, связи и ветви модели. Это правило действует для всех лабораторных. Графики измерений и поясняющие схемы можно строить отдельно, с точной подписью; они не заменяют снимок блоков.

1. Открой нужную модель, выбери область блоков и вызови `capture`. Он сохраняет PNG и `.capture.json` с хешем и окном-источником.
2. Через `capture_figure` передай `sources` — массив объектов `path` и необязательный `box: [left, top, right, bottom]`, координаты в пикселях исходного кадра. Можно собрать вертикально несколько перекрывающихся фрагментов длинной схемы. Инструмент сохраняет `.figure.json`. Не дорисовывай и не переставляй блоки/связи на снимке.
3. Проверь названия, соединения, начало/конец и все вспомогательные ветви. В ЛР5 обязательны запас поддонов, лист, поперечная подача детали, ручная подача, развилка упаковки; в 5.2 также вся цепь разгрузки и ресурс погрузчиков. Снимай 5.1 и 5.2 из их собственных ALP. Перекрывающиеся фрагменты обозначь в подписи как последовательные части одной схемы.
4. Для крупного вида допустима временная копия ALP с другой областью просмотра. Сохрани операционную инициализацию и исходную логику; не подменяй этой копией выдаваемую модель. Сохрани путь и SHA256 выдаваемого ALP рядом с исходными кадрами.
5. Вставь результат в соответствующее поле отчёта, сохрани пропорции и просмотри страницу PDF. Проверка происхождения в `finish_lab_report` отклоняет рисунок без кадра capture либо изменённые пиксели. Она не проверяет смысл: соответствие снимка заданию и читаемость проверяй визуально.

Для всех лабораторных подписи должны различать рисунки и таблицы; все рисунки нумеруются подряд. Укажи преподавателя, используй простые формулировки и фактические измерения. Сборочные статусы и логи Java храни в отдельном протоколе. В ЛР5 график производительности снимай из встроенного Capacity.
# Разрывы страниц в шаблоне ЛР5

Начало задания задаётся pageBreakBefore у заголовка. Не возвращай пустой абзац с разрывом страницы и keepNext: при длинных результатах он может создать целую пустую страницу. При изменении размера схем сохраняй пропорции и проверяй все страницы PDF.
