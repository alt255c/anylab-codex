# Лабораторные AnyLogic

Прочитай [обязательные критерии проверки](references/quality.md). Для каждой иллюстрации используй карту lab-N.figures.json рядом с шаблоном отчёта. Сверяй смысл снимка с подписью и сохраняй пропорции. Для ЛР5 все изображения в отчёте создавай заново: схемы делай программно или снимай из текущего ALP; не переноси картинки или их обрезки из чужих отчётов. Если пользователь назвал конкретный отчёт для оформления, используй его только как структуру DOCX и визуальный ориентир, не как источник изображений или готового текста. Используй inspect_reference и refill_reference по критериям. При отсутствии оригинала обозначь, какого образца не хватает.

1. Вызови `tasks` с номером лабораторной и строкой варианта, если у заданий действительно есть варианты. Собери перечень заданий и моделей. По умолчанию выполняй всю лабораторную. Не спрашивай и не печатай номер варианта для общих заданий без таблицы вариантов. Если таблица есть, но строки выбранного номера нет, используй данные пользователя или уточни только отсутствующие параметры. Открой оригинальный PDF по `official_pdf` для формул, рисунков и неоднозначных строк.
   - Для ЛР4 передай выбранную пользователем станцию как `station`, а приложенный план как `station_plan`. Без выбора создай учебный вестибюль метро. Используй один вестибюль в обоих заданиях.
   - Для ЛР5 и ЛР6 используй общую постановку, открытые примеры из `scenario.installed_examples` и темы лекций из `scenario.lecture_topics`. Передай пользовательскую идею в `addition`. Перед ЛР5 задай короткие вопросы о палитре коробок, типе/геометрии линии и подаваемой детали, если пользователь ещё не задал предпочтения. Без ответа выбери уместный вариант и используй поддерживаемые параметры `palette`, `layout`, `component` инструмента `conveyor_scenario`. В ЛР5.1 и ЛР5.2 реализуй перпендикулярную подачу детали на паллету с листом; проверь точку слияния и убедись, что деталь видна в движении. В ЛР5.2 строй линию от ConveyorEnter через средний участок до ConveyorExit: три разнесённых склада и отдельные домашние точки погрузчиков, без наложения транспорта и без лишнего поворотного стола на выходе. Сравни входную интенсивность минимум в трёх точках и измерь число обработанных коробок и незавершённую очередь. Для ЛР6 задай небольшой выбор оформления или режима движения, сохранив условия обеих задач. Без пользовательского дополнения реализуй `scenario.addition` и проверь его измерением. Укажи исходные примеры и фактические изменения.
2. Вызови `prepare_lab` с лабораторной, вариантом, именем студента, группой и новым абсолютным путём рабочего каталога. Встроенный комплект содержит обезличенные образцы. Передавай root только для явно выбранного внешнего комплекта. Используй ALP, файлы полей и ресурсы, которые вернул инструмент. Если для задания каталог содержит готовый ALP, начинай именно с него; копируй предыдущую работу только когда в каталоге указано `previous-task`.
3. Изучи [карточку работы](references/labs.md) и требования PDF. Для числового варианта заполни параметры согласно строке таблицы. В общем условии не добавляй фиктивный номер варианта; зерно моделирования укажи отдельно. Если пользователь не назначил отдельные настройки, выбери обоснованный сценарий в рамках задания и задокументируй его. Локальные лекции при наличии индексируй через `index` и подбирай фрагменты через `search`.
4. Проверь установку через `doctor`. Подготовь независимую копию каждого проекта с ресурсами. Используй `inspect` и `generate` для переименования, смены параметров и компоновки. Если нужны новые блоки, состояния, эксперименты или Java-выражения, редактируй копию ALP. При выборе языка сохраняй имена служебных классов и обновляй ссылки. Применяй цветовые изменения к сериям и осмысленные изменения геометрии там, где позволяет условие. Варьируй параметры согласно строке варианта. Учитывай пользовательские требования к трассе, палитре и наименованиям.
5. Собери и запусти каждый обязательный режим через `run` или `calibrate`. Укажи метрики числовыми Java-выражениями в контексте root. Для фиксированных сеток проверь число комбинаций и обязательных репликаций. Если замер не укладывается в бюджет, явно укажи это и согласуй изменение плана, если оно затрагивает требования задания. Для непрерывного режима отдельно проверь сценарий и задай конечный горизонт для сбора статистики. При ошибке проверь журнал IDE и повтори после исправления. Используй полный путь к модели и новые каталоги для прогонов.
6. Сделай кадры через `windows` и `capture`, когда окно отображает нужный этап. В ЛР4–ЛР6 при запросе видео открой сцену 3D и проверь движение в кадре, затем вызови `record` с HWND окна эксперимента. Для автоматического запуска отдельного 3D-показа можно вызвать `video`.
7. Для встроенного report_mode=reference используй reference-fields.json и `finish_lab_report`. Для отдельного исходного DOCX без встроенной карты полей используй `refill_reference`. Заполни все поля из fill_fields.paragraphs и замени все изображения из fill_fields.images свежими кадрами или графиками. При вызове refill_reference в keep_paragraphs и keep_images перечисли только остальные статичные элементы. Подставь студента, группу, вариант, год и преподавателя, если он задан. Если преподаватель не задан, это поле можно оставить пустым. Если одинаковое число встречается в нескольких ячейках, сверяй назначение каждой по окружающим заголовкам и исходной постановке. Если точный образец не требуется и есть DOCX и `report_fields`, заполни поля, строки таблиц и места для снимков через `fill_report` по [структуре отчёта](references/report.md). При отсутствии заполняемого шаблона используй `report` и передай совместимый локальный образец в `spec.template`, если он доступен. Отдельно приложи ALP с ресурсами, протоколы и измерения. Отметь условия, где проверен только запуск или часть эксперимента. Перед выдачей проверь соответствие каждого задания его исходным данным и отсутствие дословного заимствования из чужих отчётов.

При долгом вызове MCP используй каталоги прогонов для диагностики. После тайм-аута сначала проверь result.json и окна, чтобы не запускать тот же эксперимент дважды.

Обязательно различай категории коробок в 2D и 3D: обычные — бирюзовые с оранжевой полосой; хрупкие — оранжевый корпус; знак бокала добавляй только в 2D; ручная сборка — синий корпус; белая метка «Р» добавляется в 2D. Привязывай видимость к isFragile и isManuallyAdded, а не только к isSealed: маркировка должна сохраняться после закрытия. Для ручной хрупкой коробки сохраняй оранжевый корпус и отдельную метку ручной обработки. В 3D не рисуй знаки отдельными плоскостями над грузом: различия задавай материалами самой коробки. Не меняй классификацию или маршрутизацию ради демонстрации внешнего вида. Проверяй все сочетания флагов в открытом и закрытом состоянии; повторная генерация из шаблона обязана сохранять различия.


Оформление ЛР5 восстанавливай из `runtime/templates/presentation/lab-5.xml`: камера, окно, вкладки и navigate должны соответствовать исходному ALP. Правила записи и упаковки — в references/video.md. Обзор всей линии не подменяет исходный стартовый вид.
